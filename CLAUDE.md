# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Desktop app (Swing) for reading, interpreting and storing auction ("remates") data published in Costa Rica's Boletín Judicial. The user pastes a boletín's text into the **Boletin** form and gets the land (terrenos) and vehicle (vehículos) auctions listed with fixed columns (`ColumnasRemate`). Selected auctions are stored in a Google Sheets spreadsheet through the **Remates sincronizados** form.

## Build setup

- **Maven, standard layout**: `src/main/java`, `src/test/java`; `resources/` (boletines, `icon.png`) stays at the root and only `icon.png` is put on the classpath. Java 21. Dependencies: Google Sheets API client (`google-api-services-sheets`, `google-api-client`, `google-oauth-client-jetty` pinned to the oauth-client version `google-api-client` brings in, to avoid mixing versions). Builds go to `target/`.
- Use the Maven wrapper (`mvnw.cmd`, downloads Maven 3.9.x itself). IntelliJ: open `pom.xml` as a Maven project (`Remates.iml` only mirrors the source folders until then).
- Tests are plain `main` classes (no JUnit), exit code 0 = pass. **Do not run them (or the app) with `exec:java`**: the exec plugin hangs when the program calls `System.exit`. Run them with `java` and the classpath Maven writes to `target/classpath.txt`.
- When editing files from PowerShell 5.1, never use `Set-Content -Encoding utf8` (it writes a BOM that javac rejects).
- Sources contain accented letters (regexes like `[A-ZÁÉÍÓÚÑ]`, test strings). Everything must be compiled as UTF-8: Maven does it (`project.build.sourceEncoding`); IntelliJ needs `.idea/encodings.xml` with `PROJECT` = UTF-8 (its Maven import only marked `src/main/java`, and Windows-1252 makes `Á` an "unmappable character" error and silently garbles other accents).
- IntelliJ (Maven project) and `mvnw` share `target/`. Don't run `mvnw clean` while the user works in IntelliJ; if it happens, they need Build → Rebuild Project.

## Commands

Run from the project root (tests resolve `resources/...` relative to it). PowerShell:

```powershell
.\mvnw.cmd -q -B test-compile dependency:build-classpath "-Dmdep.outputFile=target/classpath.txt" "-Dmdep.includeScope=test"
$cp = "target\classes;target\test-classes;" + (Get-Content target\classpath.txt -Raw).Trim()
java -cp $cp Main                                                                   # run the app
java "-Dstdout.encoding=UTF-8" -cp $cp remates.ui.FiltroTextoTest                    # filter matching rules
java "-Dstdout.encoding=UTF-8" -cp $cp remates.ui.OrdenadorRematesTest               # column sorting (all real boletines)
java "-Dstdout.encoding=UTF-8" -cp $cp remates.sincronizados.SincronizadosTest       # sincronizados: changes, undo/redo, live saving (offline)
java "-Dstdout.encoding=UTF-8" -cp $cp remates.ui.ArchivosTextoTest                  # Procesados folder + reading .txt files
```

**Jar**: `.\mvnw.cmd -q -B package` also writes `target\remates.jar` (maven-shade-plugin: the app plus every library, Main-Class `Main`); run it with `java -jar target\remates.jar`.

`SincronizadosTest` uses `remates.sheets.SimuladorSheets` (test code): an in-memory spreadsheet that applies the app's batchUpdate requests (updateCells with field masks, insert/deleteDimension) and loads back like the real client, so tests compare "the file" with the app's model after any sequence of changes. Use it (via `Remates.setFuenteSheets`) for any UI check of Remates sincronizados; never test against the user's real spreadsheet without being asked.

## Architecture

- `remates.parser.BoletinParser` extracts the auctions from the text; `NumerosEs` handles Spanish number words, amounts and areas; `Cadenas` holds the text/regex helpers (`search`/`match`, `strip(chars)`, clamped `slice`, empty checks).
- `remates.model` holds immutable records: `DatosRemate` (fields common to every auction) composed into `Terreno` / `Vehiculo`, and `ResultadoBoletin`.
- `remates.ui.ColumnasRemate` is the list layout (headers, order, widths, numeric columns, `"No indicado"` filler). The last two columns of both sheets are `Afectado` (the defendant, `demandado` in both parsers) and `Estado` (always written empty — `null`, never "No indicado" — for the user to fill in). `remates.ui.Remates` is the MDI main window (JFrame titled "Remates", opens maximized, a `JDesktopPane` with menus Archivo → Nuevo boletín (Ctrl+N) / Salir and Ventana → Cascada / Mosaico / open windows); `Main` opens it with one child. `remates.ui.Boletin` is a child form (`JInternalFrame`, DISPOSE_ON_CLOSE; title "Boletín - 191" once a boletín number is known, otherwise "Boletín" / "Boletín (2)" with the window number); several can be open, each with its own data and filters, so per-form shortcuts use `WHEN_ANCESTOR_OF_FOCUSED_COMPONENT`, not `WHEN_IN_FOCUSED_WINDOW`. UI code that needs a Boletin must open it through `Remates.abrirBoletin()`. The boletín number comes only from the text (no input box; `numeroBoletin` field, used for the rows, the title and the saved file). `BuscadorTexto` is the search bar for the edict text (Ctrl+B; highlights all matches ignoring case/accents, Enter/Shift+Enter next/previous, "3 de 12"). Boletin has "Abrir archivo…" (Ctrl+O) to load a .txt (`ArchivosTexto.leer`: UTF-8 with/without BOM, falls back to Windows-1252) and saves every processed text to `Documents\Remates\Procesados\Boletin_<número>.txt` (`ArchivosTexto.carpetaProcesados()`, the real Documents folder via `FileSystemView`, OneDrive-redirected here; same text is not duplicated, a different one gets `_2`...). **Automated checks that press Procesar must run with `-Dremates.procesados=<temp dir>`** so they do not write into the user's Documents.
- `remates.ui.PanelFiltros` is the collapsible "Búsqueda y filtros" section above the result tabs: one permanent general search plus any number of column filters, applied live through each table's `TableRowSorter` row filter (tables must use a `TableRowSorter`). Filters apply **only to the visible tab** (`Boletin` calls `tablaVisibleCambio()` on tab change): the hidden table gets no row filter, value suggestions and slider positions come from the visible table only, and a column filter whose column the visible tab lacks is ignored and labelled "no aplica aquí". Matching rules live in `FiltroTexto` (accent/case-insensitive words; `> < >= <= =` on numbers and dd/mm/yyyy dates; `rango(min, max)` for numeric columns), tested by `remates.ui.FiltroTextoTest`. For `ColumnasRemate.NUM_COLS` and `FECHA_COLS` (dd/mm/yyyy) a filter row also shows a range: mín/máx boxes kept in sync with `SelectorRango` (custom two-handle slider whose positions are the column's distinct values, so skewed amounts spread evenly); text and range are ANDed. The boxes are prefilled with the visible column's min/max (also after Restablecer, a column change, or a tab switch if untouched); a bound at or beyond the column's extreme counts as "no limit", so a range only filters (and hides "No indicado" rows) once narrowed. Date bounds are handled as epoch days (`TipoRango` in `PanelFiltros`). Search terms (`FiltroTexto.terminos`, any text box): plain words required, `-palabra` excluded (general search: no column may contain it), `+a +b` at least one of them. Exclusion also via an Incluir/Excluir combo per row that negates (text AND range) — Excluir + range keeps values outside it and "No indicado" rows; and, for text columns, a checkbox value list whose unticked values are hidden in both modes (stored by displayed text, kept across tabs). `CampoBorrable` is the text field with a built-in clear button.
- Both forms show their result tables through `NumerosFila` ("#" row-number column as the scroll pane's row header: numbers the visible rows after filtering/sorting, click selects full rows; `refrescar()` also copies row heights). Result tables use `remates.ui.OrdenadorRemates` as row sorter (not a plain `TableRowSorter`): the model declares every column as `Object`, so the default sorter compares `toString()` (amounts as text, dates by day). It compares numbers, dd/mm/yyyy dates and digit-only text by value, other text with a Spanish `Collator`, and keeps "No indicado"/empty last in both directions.
- **Remates sincronizados** (Google Sheets):
  - `remates.sheets`: `ConfiguracionSheets` (settings in `%USERPROFILE%\.remates\`: `credentials.json` = OAuth client of type "Desktop app", `tokens\` = stored sign-in, `config.properties` = spreadsheet ID; never in the repo), `ClienteSheets` (sign-in with the user's Google account, scope `spreadsheets` only; loads tabs "Terrenos" / "Vehiculos" (`ColumnasRemate.HOJA_TERRENOS` / `HOJA_VEHICULOS`) with values and `userEnteredFormat`; sends one `batchUpdate` per batch; missing tab = error, empty tab = header written), `LectorHoja` (sheet → model, columns matched by header name so extra/reordered sheet columns are fine; columns the sheet lacks get their header appended at the end on load; an empty `Estado` stays ""), `FuenteSheets` (interface so tests plug in `SimuladorSheets`).
  - `remates.sincronizados`: model (`HojaSincronizada` → `FilaSincronizada` → `CeldaSincronizada` with value, `Formato` and an unsaved flag), `Peticiones` (request builders; rows are addressed by position: model row i = sheet row i+1), undoable `Cambio`s in `Cambios` (EditarCelda, FormatearCeldas, EliminarFilas, AgregarFila, ReemplazarValores — each computes its requests when applied/reverted, from current positions), `Historial` (undo/redo), `ColaGuardado` (live saving: immediate; changes made while a request is in flight go together next; typed values wait 1.5 s; failures flag cells light red, stay first in the queue and are retried). `Formato.CAMPOS` is the field mask: only background, font color/size, bold/italic/underline/strikethrough and alignment are ever written, so other formatting in the file is kept.
  - UI: `remates.ui.RematesSincronizados` (single instance, `Remates.abrirSincronizados()`; asks `DialogoCredenciales` when settings are incomplete; the save queue sends through `enviarConSesion`, which always uses the current connection and, on an expired/revoked sign-in (`ClienteSheets.esSesionInvalida`), signs in again and resends the same batch — never capture a `FuenteSheets` in the queue); while connecting/loading, `IndicadorCarga` (a `JLayer` over filters and tables) dims and blocks them and shows a spinner, the step and the seconds elapsed, shared table setup in `TablasRemates` (also used by `Boletin`; per-cell `Estilo` hook; the selected (lead) cell's row and column are tinted and its column header lightened — `resaltarCruz` repaints the table when the lead cell moves; no column tint for full-row selections), `DialogoDiferencias` (same Referencia N° added again). `Boletin` adds a row by double-click (`Remates.agregarASincronizados`: sincronizados is not brought to the front — opened behind if closed — and scrolls to the added row; the Boletín keeps the focus) and paints rows whose Referencia N° is in sincronizados light green (`Remates.estaSincronizado`, refreshed via `Remates.refrescarMarcas()`).
- `remates.ui.IconoApp` reads the window icon from `resources/icon.png` (ImageIO) and scales it to each size (halving steps, bicubic). It reads `/icon.png` from the classpath first, then `resources/icon.png` relative to the working directory. Replacing the PNG changes the icon with no other step.

## Parser conventions (important)

- Compile every pattern through `Cadenas.re` / `Cadenas.rei`: they add `UNICODE_CHARACTER_CLASS`, without which `\b`, `\w`, `\s` misbehave next to accented letters (á, É, ñ) and fields such as province are silently lost.
- `Cadenas.match` is anchored at the start (`lookingAt`); `Cadenas.strip` also strips non-breaking spaces, unlike `String.strip`.
- Edict detection: a line containing `sáquese a remate` / `sáquese en remate` (case-sensitive) is one auction; its `Referencia N°` is searched in the next 9 lines. The boletín number comes from `número NNN` or `Boletín Judicial N° NNN` in the first 20 lines (`BoletinParser.detectarNumero`; text copied from the web page starts with navigation lines).
- Known quirk kept on purpose: in `rematesPosteriores` the 2nd-auction segment end is `m2.end() + f.start()` (double offset); changing it changes extracted rows.
